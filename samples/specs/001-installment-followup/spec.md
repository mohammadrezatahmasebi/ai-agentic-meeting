# Spec 001 — پیگیری اقساط معوق (Installment Follow-up)

## هدف / Goal
فروشنده/کارشناس بتواند اقساط معوق یک بیمه‌نامه را شناسایی کند و اقدام follow-up ثبت کند تا وضعیت پیگیری شفاف شود.

## کاربر و داستان‌ها
- به‌عنوان **فروشنده**، می‌خواهم لیست اقساط معوق مشتری را ببینم تا تماس بگیرم.
- به‌عنوان **فروشنده**، می‌خواهم نتیجه پیگیری (تماس، پیامک، وعده پرداخت) را ثبت کنم.
- به‌عنوان **سرپرست**، می‌خواهم تاریخچه follow-up یک قسط را ببینم.

## معیار پذیرش / Acceptance Criteria
1. Given یک قسط با بیش از ۳۰ روز تأخیر، When لیست follow-up درخواست شود، Then آن قسط در نتیجه با برچسب `Overdue` ظاهر شود.
2. Given یک قسط معوق، When کاربر follow-up با نوع و توضیح ثبت کند، Then رکورد با `CreatedAt` و `CreatedBy` ذخیره شود.
3. Given follow-up ثبت‌شده، When جزئیات قسط خوانده شود، Then تاریخچه follow-upها به‌ترتیب جدید به قدیم برگردد.
4. Given ورودی نامعتبر (نوع خالی یا InstallmentId ناموجود)، When درخواست ثبت شود، Then خطای اعتبارسنجی/NotFound برگردد و چیزی ذخیره نشود.
5. فیلد مبلغ فقط `decimal` باشد.

## خارج از محدوده / Non-goals
- ارسال خودکار پیامک/ایمیل در این نسخه
- محاسبه جریمه دیرکرد
- UI وب کامل (فقط API)

## قوانین دامنه مرتبط (از مستندات کسب‌وکار)
- اقساط معوق بیش از ۳۰ روز باید قابل پیگیری باشند.
- هر اقدام پیگیری باید قابل ممیزی (چه کسی / چه وقت / چه کرد) باشد.

## لبه‌ها و خطاها
- قسط پرداخت‌شده نباید در لیست معوق بیاید.
- کاربر بدون دسترسی فروش نباید بتواند follow-up ثبت کند (اگر auth در پروژه هست).

## وابستگی‌ها
- جدول/موجودیت Installment
- احراز هویت فعلی Host
